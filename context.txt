Known current architectural limits
- Actual Wi-Fi is not implemented.
  - network.c currently has a real RTL8139 Ethernet packet driver.
  - network_wifi_connect() only stores an SSID/profile and reports that a wireless driver is not implemented.
  - There is no chipset-specific wireless driver or firmware loader in the repo yet.
  - There is also no in-repo 802.11 MAC/auth/association stack, scan path, or chipset-specific initialization path for any Wi-Fi hardware.
  - This means "implement wireless driver" is not one generic change here; it requires choosing a concrete wireless chipset family and building to that hardware.
- Actual persistent disk install is not implemented at the block-driver level.
  - drivers.c can detect storage controllers.
  - There is no ATA, AHCI, or NVMe block driver yet.
  - The current install target model is more honest and useful than before, but it is still not a real on-disk bootable installation path.
- Keyboard input is still the old simple driver until keyboard.c and shell.c are finished.

Wireless assessment from the latest inspection
- drivers.c detects wireless-class PCI devices and stores first_wireless metadata, but does not initialize any wireless hardware.
- network.c only initializes RTL8139 Ethernet.
- The current Wi-Fi path is just:
  - save SSID/profile
  - report "wireless driver not implemented yet"
- A real Wi-Fi implementation would need, at minimum:
  - one chosen chipset family
  - chipset register/DMA init
  - RX/TX ring handling
  - 802.11 frame handling
  - scan/auth/assoc logic or a much simpler chosen scope
  - possibly firmware loading depending on chipset
